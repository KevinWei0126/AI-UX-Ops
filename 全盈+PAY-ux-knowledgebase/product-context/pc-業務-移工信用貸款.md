# 玉山 × 全盈+PAY 移工信用貸款業務脈絡

## 摘要（TL;DR）
玉山銀行與全盈+PAY 合作推出**移工信用貸款**：全盈+PAY 承接前端用戶體驗（申貸曝光入口、試算、資料授權預填、Webview 嵌入玉山申請/還款介面、電支帳戶作為撥款與還款帳戶、進度查詢），玉山銀行負責後端金融（信用審核、核貸、對保簽約、資金撥付與還款處理）。目標是整合「試算→申貸→撥款→還款」流程，降低門檻、提升移工金融服務可及性。資料來源為 PM 提供之業務架構簡報（2026-06）。

## 詳細內容

### 背景與脈絡
- 全盈+PAY 定位為「申貸曝光入口 + 提供用戶資料以降低申請門檻」；玉山負責信用審核與資金提供。
- PM 提出三大服務痛點（**尚未經一手用戶驗證**）：①申貸流程門檻高且繁瑣 ②缺乏整合式數位體驗 ③跨語言溝通障礙。
- 核心模式：**電子支付承接前端用戶體驗、銀行負責後端金融服務，透過系統串接形成完整服務鏈**。

### 現況描述（三方分工）
| 角色 | 負責範圍 |
|---|---|
| **全盈+PAY** | 用戶入口與申貸導流、試算與流程引導、資料授權、Webview 嵌入玉山申請/還款介面、電支帳戶作為撥款/還款帳戶、還款進度查詢 |
| **玉山銀行** | 信用貸款審核與核貸、對保簽約、放款與還款處理 |

### 核心用戶流程（8 步）
試算 → 同意條款 → 導轉玉山 → 申請填寫 → 等待審核 → 對保流程 → 撥款至電支錢包 → 以電支錢包還款。
> 主導方：試算/同意條款/對保綁定/撥款入電支/觸發還款由**全盈**主導；申請填寫/審核/放款由**玉山**主導；「申請填寫、個人資訊、確認申請資料」等頁面依玉山既有設計為主。

### 金流與撥款/還款
- **撥款**：玉山匯款 → 儲值至全盈信託銀行帳戶 → 撥款至用戶電支帳戶 → 全盈提供批次代發規格檔（撥貸總額、每用戶金額、交易明細）→ 推播告知用戶。
- **還款**：拋檔 → 推播通知用戶還款 → 用戶電支帳戶還款 → 轉入全盈信託帳戶 → 匯款玉山。款項實際皆存放於全盈的信託銀行帳戶內。
- 備註：**還款兼具「新增交易額」的作用**；TA 為完成身分驗證者。

### 資料共享範圍（to C 條款）
- **基本資料**：姓名、性別、出生年月日、國籍、身分證字號、手機、email、戶籍/居住地址、在台時間、公司、行業別、年資、公司地址。
- **附加資料**：消費動態（消費特店類別、每月平均每筆/每月消費金額）、資金流向（每月平均儲值金額、提領次數、綁定儲值帳戶餘額、主要綁定帳戶/信用卡）。

### 對保與還款作業
- 指定全盈電支帳戶作為**撥入帳戶（驗身）** 與**扣款帳戶**，綁定訂閱制授權扣款（約定授扣）。
- 手動還款：選擇手動還款 → 跳轉玉山確認 → 跳轉全盈付款畫面完成付款。

### 曝光入口策略
- **既有會員**：全家 SDK、One APP 金融服務專區、首頁、交易結果頁、廣告蓋板、MGM。
- **非會員**：多語系落地頁、試算前置、免裝 App 先試算、通路專屬追蹤連結、QR Code 線下觸及、廣告落地頁（FB/TikTok A/B 測不同語言）。
- **推廣**：移工對 App 不熟但族群凝聚力強 → 口碑 + 仲介通路（如美家）為優先管道；MGM 推薦碼。

### 關鍵限制
- 中間申請/審核頁面**依玉山既有設計為主**，全盈前端可設計範圍集中在入口、試算、同意授權、對保綁定、還款進度與撥款體驗。
- 檔案規格（代發檔/拋檔）、還款約定時間需雙方定義。
- 需符合金管會對外籍移工金融服務的相關規範。

### 與設計相關的重點
- 前端設計主戰場在全盈側；玉山 Webview 的**銜接與信任感**是體驗關鍵斷點。
- 資料共享範圍大，**授權揭露方式**直接影響移工接受度（見 r2026-07-001 詐騙戒心發現）。
